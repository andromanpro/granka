# Конфигурация

Гранка читает `granka-config.json` рядом с приложением. Другой файл задаётся
через `GRANKA_CONFIG`. Относительные пути считаются от конфигурации;
поддерживаются `~` и переменные окружения. После изменения путей нужен перезапуск.

Пример `granka-config.example.json` содержит только учебные значения.
Скопируйте его в локальный файл и укажите свои каталоги.

Для обычного открытия статей конфиг не нужен: библиотека предлагает выбор
файла и папки. Выбранные источники хранятся отдельно в личном
`library-locations.json`; конфиг и тексты при подключении не переписываются.
Один файл подключается отдельно от соседних. Папка читается вместе с вложенными
каталогами. Источники доступны сразу и сохраняются после перезапуска.

Системное окно использует Tk из поставки Python. Если в вашей сборке Tk
отсутствует или нет рабочего графического сеанса, используйте ручной путь
в библиотеке. Сервер и браузер должны работать на одном компьютере.

| Раздел | Настройки |
|---|---|
| `server.port` | Локальный порт; адрес прослушивания остаётся loopback |
| `roots` | Идентификатор → каталог статей; можно задать несколько папок |
| `image_dirs` | Дополнительные каталоги галереи |
| `planning.source_dirs` | Рабочий корень → список относительных папок черновиков; пустой объект использует все корни |
| `corrections_file` | Личный список редакторских предпочтений |
| `voice` | Каталог рукописей и файл калибровочного профиля |
| `speech` | Python с faster-whisper, модели, язык, кэш и offline |
| `ai` | Исполнители и модели; также настраиваются в интерфейсе |
| `codex_binary` | Необязательный путь к Codex CLI; иначе поиск в окружении |
| `openrouter_key_file` | Необязательный файл ключа; приоритет у OPENROUTER_API_KEY |
| `site` | Включение публикации, репозиторий, remote и три контура |
| `git.bypass_proxy` | Явно отключить proxy только для Git; по умолчанию сохраняются настройки окружения |
| `feedback.command` | Необязательный массив аргументов команды с `{text}`; без оболочки |

## Папки календаря

По умолчанию календарь читает Markdown и разметку из `roots`. Чтобы отделить
черновики от исследовательских заметок, задайте папки относительно этих корней:

```json
{
  "planning": {
    "source_dirs": { "articles": ["drafts"], "blog": ["."] }
  }
}
```

Ключи должны существовать в `roots`; выход за пределы корня запрещён.
Файлы README, AGENTS и другие служебные документы, папки `.assets` и исходники
со статусом `publish` пропускаются. Дата в frontmatter черновика не назначает
публикацию автоматически. Даты и исключения живут в личном состоянии календаря.

## Контуры WordPress

Ключи контуров: `nas` (предпросмотр), `staging`, `prod`.
У каждого задаются `label`, `url`, массив аргументов `ssh` и массив `wp`.
Для WordPress в Docker дополнительно укажите `container` и, при необходимости,
путь `docker`. Настройки команд должны быть доверенными и локальными.

```json
{
  "site": {
    "enabled": true,
    "repository": "./blog-content",
    "remote": "https://git.example.invalid/editor/blog-content.git",
    "environments": {
      "nas": {
        "label": "Предпросмотр",
        "url": "https://preview.example.invalid",
        "ssh": ["preview-server"],
        "wp": ["wp", "--path=/srv/wordpress"]
      },
      "staging": {
        "label": "Стейдж",
        "url": "https://staging.example.invalid",
        "ssh": ["staging-server"],
        "wp": ["~/bin/wp", "--path=~/sites/staging"]
      },
      "prod": {
        "label": "Прод",
        "url": "https://www.example.invalid",
        "ssh": ["production-server"],
        "wp": ["~/bin/wp", "--path=~/sites/production"]
      }
    }
  }
}
```

Настройте SSH-алиасы и права WP-CLI вне приложения. У Git-репозитория должны
быть ветка из `site.branch` (по умолчанию `main`), remote `origin` с указанным адресом и собственные
`user.name`/`user.email`. Движок Markdown входит в Гранку; дополнительные
скрипты в репозитории контента не нужны.

## Корпус

Кладите собственные рукописные Markdown-файлы в `voice.corpus_dir`.
Доклады можно отделить подпапкой `talks`. Не добавляйте инструкции, чужие
статьи и сгенерированные тексты в калибровку своего голоса.

Для явно выбранных DOCX доступен `tools/import-voice-archive.py`:

```sh
python tools/import-voice-archive.py --profile talks ./my-talk.docx
```

Импортированный текст и сведения об источнике сохраняются в личном каталоге.
Они не предназначены для распространения вместе с приложением.
