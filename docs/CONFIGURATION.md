# Конфигурация

Гранка читает `granka-config.json` рядом с приложением. Другой файл задаётся
через `GRANKA_CONFIG`. Относительные пути считаются от конфигурации;
поддерживаются `~` и переменные окружения. После изменения путей нужен перезапуск.

Пример `granka-config.example.json` содержит только учебные значения.
Скопируйте его в локальный файл и укажите свои каталоги.

Для обычного открытия статей конфиг не нужен: библиотека предлагает выбор
файла и папки. Выбранные источники хранятся отдельно в личном
`library-locations.json`; конфиг и тексты при подключении не переписываются.
Один файл подключается отдельно от соседних. Папка читается вместе с вложенными
каталогами. Источники доступны сразу и сохраняются после перезапуска.

Системное окно использует Tk из поставки Python. Если в вашей сборке Tk
отсутствует или нет рабочего графического сеанса, используйте ручной путь
в библиотеке. Сервер и браузер должны работать на одном компьютере.

| Раздел | Настройки |
|---|---|
| `server.port` | Локальный порт; адрес прослушивания остаётся loopback |
| `roots` | Идентификатор → каталог статей; можно задать несколько папок |
| `image_dirs` | Дополнительные каталоги галереи |
| `planning.source_dirs` | Рабочий корень → список относительных папок черновиков; пустой объект использует все корни |
| `corrections_file` | Личный список редакторских предпочтений |
| `voice` | Каталог рукописей и файл калибровочного профиля |
| `speech` | Python с faster-whisper, модели, язык, кэш и offline |
| `ai` | Исполнители и модели; также настраиваются в интерфейсе |
| `codex_binary` | Необязательный путь к Codex CLI; иначе поиск в окружении |
| `openrouter_key_file` | Необязательный файл ключа; приоритет у OPENROUTER_API_KEY |
| `site` | Включение публикации, репозиторий, remote и три контура |
| `git.bypass_proxy` | Явно отключить proxy только для Git; по умолчанию сохраняются настройки окружения |
| `feedback.command` | Необязательный массив аргументов команды с `{text}`; без оболочки |

## Папки календаря

По умолчанию календарь читает Markdown и разметку из `roots`. Чтобы отделить
черновики от исследовательских заметок, задайте папки относительно этих корней:

```json
{
  "planning": {
    "source_dirs": { "articles": ["drafts", "separate-article.md"], "blog": ["."] },
    "excluded_sources": { "articles": ["drafts/old-version.md", "drafts/editorial-notes"] },
    "publications": [
      { "root": "articles", "file": "drafts/article.granka.json",
        "url": "https://www.example.invalid/article/", "date": "2026-10-16" }
    ]
  }
}
```

Ключи должны существовать в `roots`; выход за пределы корня запрещён.
Можно выбирать папки или отдельные Markdown-файлы. Файлы README, AGENTS,
другие служебные документы и папки `.assets` пропускаются. Дата в frontmatter
черновика не назначает публикацию автоматически. Даты и исключения живут
в личном состоянии календаря.

`excluded_sources` убирает указанные файлы или подпапки из выдачи без удаления
с диска. Пути задаются относительно корней. Исключение Markdown также скрывает
его разметку. При этом новые статьи в выбранной папке появляются автоматически.

Опубликованные материалы показываются отдельным фильтром библиотеки и в
календаре, с готовностью 100%. Статус берётся из метаданных `publish`/`published`,
успешной квитанции продакшена или явной связи `planning.publications`.
Последнюю добавляйте после проверки фактической публикации: нужны корень,
относительный путь разметки `.granka.json` (файл может ещё не существовать),
публичный HTTP(S)-адрес и дата выхода. Эта связь не редактирует статью и не
публикует её. Она имеет приоритет над устаревшим состоянием черновика в плане.

Копии с одним подтверждённым адресом объединяются; другие исходники можно
раскрыть. В карточке доступна ссылка на публикацию. Если локального исходника
нет, создайте в календаре материал со статусом «Опубликовано», датой и ссылкой,
без привязки файла — он также появится в библиотеке. Это ссылка на готовую
публикацию, текст при открытии не скачивается и новый исходник не создаётся.

## Площадки WordPress

Подключение настраивается в интерфейсе: **Настройки → Публикация на сайт**.
Достаточно одного WordPress с SSH и WP-CLI. NAS, стейдж, Docker и Git
не являются обязательными компонентами. Поддержка WordPress REST API
и сервисов без SSH в эту версию не входит.

`site.pipeline` — упорядоченный список идентификаторов из `site.environments`.
Допускается до восьми площадок; идентификаторы произвольные, из латинских букв,
цифр, дефиса и подчёркивания, начиная с буквы. Последняя площадка получает
выбранный статус `draft`/`publish`; остальные публикуют страницы для проверки.
Площадка вне pipeline сохраняется в конфиге, но не участвует в переносе.
У каждой задаются `label`, `url`, массив аргументов `ssh` и массив `wp`.
Для WordPress в Docker дополнительно укажите `container` и, при необходимости,
путь `docker`. Настройки команд должны быть доверенными и локальными.

Для каждого подключения доступно необязательное поле `ssh_proxy`:

- поле отсутствует или пустое — прямое SSH-подключение;
- `"system"` — системный прокси: HTTPS, затем HTTP, затем общий;
- URL `http://`, `https://`, `socks5://` или `socks5h://` — указанный прокси.

HTTP использует CONNECT, SOCKS5 — подключение с разрешением имени на прокси.
Пароль в URL не поддерживается и не выводится в настройках. Если выбран
системный прокси, но его нет, Гранка останавливает операцию с сообщением;
скрытого перехода к прямому подключению нет. Глобальные настройки SSH и прокси
не изменяются. Новый маршрут применяется к следующей операции без перезапуска;
уже начатая операция использует свой снимок конфигурации.

**Сохранить настройки** атомарно сохраняет маршруты и параметры ИИ в локальном
JSON с проверкой ревизии и межпроцессной блокировкой. При конфликте откройте
форму заново. Сохранение не проверяет сервер и ничего не публикует — для этого
используйте отдельный предпросмотр перехода на нужный контур.

```json
{
  "site": {
    "enabled": true,
    "pipeline": ["blog"],
    "git_enabled": false,
    "environments": {
      "blog": {
        "label": "Мой блог",
        "url": "https://blog.example.invalid",
        "ssh": ["-p", "22", "publisher@host.example.invalid"],
        "wp": ["wp", "--path=/var/www/blog"]
      }
    }
  }
}
```

Для схемы «проверочный сайт → основной сайт» добавьте второе подключение,
например `preview`, и укажите `"pipeline": ["preview", "blog"]`.
Смена адреса, SSH/WP-параметров, Git или порядка требует нового снимка:
старая подготовка не отправляется на новую площадку. Название и маршрут
прокси не меняют содержимое снимка и применяются к следующей операции.

Git включается только при `site.git_enabled: true`: добавьте `repository`,
`remote` и при необходимости `branch`. У Git-репозитория должны
быть ветка из `site.branch` (по умолчанию `main`), remote `origin` с указанным адресом и собственные
`user.name`/`user.email`. Движок Markdown входит в Гранку; дополнительные
скрипты в репозитории контента не нужны.

Совместимость: если pipeline отсутствует, прежние ключи `nas`, `staging`, `prod`
читаются в старом порядке, затем добавляются другие подключения. Если
git_enabled отсутствует, прежние repository+remote включают Git, как раньше.
Квитанции старого формата продолжают читаться без перезаписи; их последний
этап — `prod`. Изменения подключения не выполняют публикацию автоматически.

## Корпус

Кладите собственные рукописные Markdown-файлы в `voice.corpus_dir`.
Доклады можно отделить подпапкой `talks`. Не добавляйте инструкции, чужие
статьи и сгенерированные тексты в калибровку своего голоса.

Для явно выбранных DOCX доступен `tools/import-voice-archive.py`:

```sh
python tools/import-voice-archive.py --profile talks ./my-talk.docx
```

Импортированный текст и сведения об источнике сохраняются в личном каталоге.
Они не предназначены для распространения вместе с приложением.
## Настройки в рабочей мастерской

Параметры исполнителя и оформление доступны через **Настройки** в левом
меню. Бот и канал настраиваются в **Telegram → Бот и канал**.
Поле **Публикация** выбирает отправку **от имени канала через бота** или
**вручную в Telegram**. Во втором режиме Гранка сохраняет черновик и копирует
текст, но не отправляет его. Медиа и аватар отправителя выбираются в Telegram.
Режим хранится в личных настройках, не в статье и не в машинном конфиге;
вход в личный Telegram-аккаунт не выполняется. После выбора нажмите
**Сохранить настройки Telegram**. Прежняя конфигурация остаётся в режиме канала.
Маршрут со снимками экранов — в [справке](USER-GUIDE.md).
