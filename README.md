# Гранка

<img src="static/brand/mark.svg" width="72" height="72" alt="Знак Гранки" />

Локальный редактор статей: оформленный Markdown, замечания ИИ, авторские
решения, история версий, иллюстрации и подготовка публикаций.

ИИ предлагает правки к точным цитатам. Автор выбирает, что принять,
что оставить и где редактору пора отойти от клавиатуры.

![Гранка: учебная статья и карточки редакторских замечаний](docs/images/workbench.png)

[Справка с актуальными экранами](docs/USER-GUIDE.md): библиотека, редактор,
приправы, сравнение, история, календарь и публикации. В самой Гранке она
открывается кнопкой **Справка** в левом меню. Снимки сделаны на учебной статье.

В рабочей версии Telegram различает обновление прежнего поста и создание нового,
с защитой от одновременной отправки из двух окон. Маршруты подключения к контурам
сайта настраиваются через **Настройки → Публикация на сайт**. Подключите свой
WordPress по SSH/WP-CLI: один сайт работает без NAS, стейджа и Git.
Промежуточные площадки и сохранение в Git включаются по необходимости.
Новая установка не содержит адресов, ключей или токенов автора.

## Быстрый старт

### Готовая поставка Windows

В [выпусках](https://github.com/andromanpro/granka/releases) доступны установщик
`Granka-<версия>-Setup-x64.exe` и переносимый ZIP для Windows 10/11 x64.
Python, библиотеки и Codex входят в поставку; отдельно ставить Python и Node.js
не нужно. Установка выполняется для текущего пользователя без администратора.
Запуск — через ярлык **Гранка**, вход в ИИ — **Пуск → Гранка → Войти в ChatGPT**.
Редактор работает и без подключения ИИ.

Установщик пока без цифровой подписи: Windows может показать неизвестного
издателя. Контрольные суммы идут в `SHA256SUMS.txt`. Инструкция установки,
обновления и удаления: [docs/WINDOWS.md](docs/WINDOWS.md).

### Из исходников

Основная проверенная версия Python — 3.14.

```sh
python -m pip install -r requirements.txt
python launch-granka.py
```

На Windows можно использовать `py -3` вместо `python`.
Откроется `http://127.0.0.1:8901/`. Сервер слушает только локальный интерфейс.
Повторный запуск использует работающий сервер; `--no-browser` не открывает вкладку.

Без конфигурации статьи хранятся в личном каталоге приложения. **Новая статья**
в библиотеке и верхней панели открывает мастер: тема, пустой черновик/разделы/заметки,
папка и два создаваемых файла. Обязательно только название; цель и аудитория
не попадают в текст. Совпадающие названия получают разные имена файлов.
Дата публикации не назначается. Пустой черновик, разделы и свои заметки
создаются локально без запроса к ИИ.

Четвёртый вариант — **Заготовка с ИИ**. Укажи факты и заметки, выбери объём
и авторский профиль. При включённом «Писать в моём стиле» используются личные
правила, примеры решений и до трёх коротких фрагментов подключённого корпуса.
Можно заранее выбрать приправы, готовый или собственный рецепт: они влияют
на содержание образов, композицию и подачу первого текста. Смесь разовая.
**Написать заготовку** запускает выбранного текстового исполнителя с его тарифами.
Полученный текст можно править; файлы появятся только после **Создать статью**.
Модель не должна выдумывать факты и личный опыт: недостающее помечается для
уточнения автором. В этой же вкладке можно восстановить запуск после обновления;
**Проверить запуск** использует прежний идентификатор, автоматических повторов нет.

Для существующего материала нажмите **＋**,
затем **Открыть файл…** или **Добавить папку…**: появится обычное системное окно
выбора. Источники запоминаются локально и доступны сразу, включая календарь.
При выборе одного файла соседние статьи не подключаются. Ручной путь доступен
в раскрываемом блоке библиотеки, если системное окно недоступно.

Для расширенной настройки скопируйте `granka-config.example.json` в
`granka-config.json`. Относительные пути считаются от файла конфигурации.
Настройки: [docs/CONFIGURATION.md](docs/CONFIGURATION.md).

Кнопка **＋** открывает Markdown из настроенных папок. Рядом со статьёй
создаётся файл `<имя>.granka.json`. Пример: [examples/article.md](examples/article.md).

Чтобы познакомиться с замечаниями без запроса к ИИ, откройте через библиотеку
файл `examples/review.granka.json`: появится учебная статья с готовой разметкой.
Она показана на скриншоте выше. Примеры можно свободно редактировать.

Библиотека использует те же папки, что календарь, и показывает названия
из заголовков статей. Фильтры отделяют черновики от опубликованного.
Связанные экспортные копии и совпадающие исходники доступны в раскрываемом
списке «Другие исходники». Кнопка «В календарь» открывает план, а исключённый
материал можно вернуть в него прямо из библиотеки.

На карточке статьи и в списке «Другие исходники» есть **В корзину**. Перед
переносом показываются локальные файлы: Markdown, разметка со всеми версиями
и папка материалов. Другие исходники той же карточки остаются в библиотеке.
**Корзина** вверху библиотеки позволяет восстановить статью в прежнюю папку;
занятые имена не перезаписываются. Общие материалы других статей остаются на месте.
**Очистить корзину → Удалить навсегда** удаляет архивные файлы после отдельного
подтверждения. Внешние публикации и их квитанции сохраняются. Перенос ссылки без
локального исходника убирает только её локальную карточку. Даты и заметки плана
возвращаются при восстановлении, а удалённые материалы не попадают в экспорт Blatero.

Blatero может открыть конкретный исходник прямо из карточки задачи. Ссылка
с параметрами `root` и `source_file` выбирает Markdown по относительному пути,
включая исходник внутри «Других исходников». При первом открытии создаётся
разметка Гранки; Markdown сохраняется. Удалённый или исключённый источник
показывает сообщение об отсутствии статьи. Ссылки `root` + `f` продолжают
открывать существующую разметку, а `source` — поиск по названию в библиотеке.

У опубликованной статьи видны дата и ссылка «Читать публикацию». Подтверждённые
публикации с одним адресом собираются в одну карточку, даже если исходники
лежат в разных папках. Статус из метаданных, квитанции или явной связи
в конфигурации исключает материал из автоматического планирования.
Старую публикацию без локального текста можно добавить в календаре с датой
и ссылкой — её карточка откроет готовую страницу.

Ярлык Windows с иконкой:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/install-shortcut.ps1
```

## Работа

Постоянное меню слева открывает **Статьи**, **Редактор**, **Приправы**,
**Изменения**, **Историю**, **Календарь**, **Telegram** и **Настройки**.
Статья остаётся в редакторе при переходах между разделами. Библиотека,
календарь и подготовка Telegram занимают отдельные экраны; окно выбора
картинки и подтверждения открываются поверх них. В узком окне меню
сворачивается до значков, а инструменты статьи открываются отдельной панелью.

В **Настройках → Оформление** можно выбрать Georgia или Segoe UI,
размер текста и отключить анимацию. Эти предпочтения сохраняются в данном
браузере; системное ограничение движения учитывается независимо от них.
Тёмная мастерская использует графитовую палитру и знак со скобочками.

- Печатайте прямо в тексте. **Сохранить** или `Ctrl+S` создаёт новую версию;
  `Ctrl+Z` отменяет ввод. Есть отдельный режим исходника.
- **Проверить текст** готовит замечания с точными цитатами. Выберите замену,
  собственный вариант или причину отказа.
- **Применить решения** собирает новую версию и показывает сравнение.
  Незавершённый ввод можно восстановить после перезагрузки.
- Во вкладке **История** доступны все версии: **Открыть** показывает снимок,
  **Сравнить с открытой** сопоставляет его с выбранной версией,
  **Вернуть в работу** создаёт новую версию с прежними текстом, обложкой
  и пометками. Более поздние версии сохраняются.
- Во вкладке **Изменения** можно выбрать любые левую и правую версии
  и поменять их местами. Сравнение само по себе не меняет статью.
- Вставка `[придумай короткую аналогию]` становится поручением редактору.
  Вопросы о личном опыте остаются автору. Код и цитируемые примеры пропускаются.
- **Картинка** открывает галерею и генерацию. **Обложка** хранится отдельно
  от текста и сохраняется в истории версий.
- Микрофон позволяет связать голосовую заметку с выделением.

При переходе к другой статье или версии с несохранённым текстом Гранка
предлагает сохранить правки, перейти без сохранения или остаться. Ошибка
сохранения останавливает переход. Закрытие или обновление вкладки защищает
стандартное предупреждение браузера; незавершённый текст хранится локально.

Вне полей ввода: `J/K` — переход по карточкам, `1–9` — вариант,
`Enter` — принять. Git использует настроенное пользователем авторство.

## ИИ и личный голос

Во вкладке **Приправы** справа можно добавить или убавить иронию, пошлые
шутки, метафоры и аллегории. Перетащите флакон на абзац, либо нажмите
**Выбрать абзац**, **Выделение** или **Вся статья** и запустите обработку.
Перетаскивание применяет выбранную приправу; кнопка использует всю смесь.
Гранка сначала показывает предложения с вариантами. Выберите нужные,
при желании отредактируйте формулировку и нажмите **Применить выбранное**.
Появится новая версия со сравнением; исходный текст остаётся в истории.

**Сохранить свой рецепт** запоминает название, состав, дозировки, действие,
количество и пожелание. Свободное задание работает и без готовых приправ.
Личные рецепты можно обновлять и удалять; общие авторские правила от этого
не меняются. В настройках выбираются флаконы или текстовая панель, рябь,
блик либо отсутствие движения. Оба оформления находятся справа от статьи.
При несохранённой правке сначала сохраните текст и заново выберите область.
Генерация использует выбранного исполнителя анализа, включая его тарифы.

**Мои правила** показывает личные предпочтения из `corrections_file` и число
прошлых решений. При анализе учитываются правила и до 16 подходящих примеров;
копии одной карточки между версиями не увеличивают её вес.

У новых замечаний есть конкретное правило. Если оно повторяется, можно открыть
пакет, выбрать фрагменты и варианты и сохранить решения одним действием.
Пакет не переписывает текст: используется обычная команда **Применить решения**.
Последний пакет можно отменить, пока его решения не менялись отдельно.

В окне правил доступен проверочный набор из авторских решений. **Обновить набор**
сохраняет его снимок, **Проверить модель** запускает отдельный запрос. Правильные
ответы не передаются модели. Сравнивается выбор «сохранить/изменить» и отсутствие
отвергнутых вариантов; смысл новой замены нужно оценить вручную. Если в наборе
нет примеров сохранения, он не измеряет склонность модели к лишним правкам.

Правила, проверочные примеры и результаты остаются в личном каталоге данных.

**Предложить уточнения** ищет предпочтения в прошлых решениях и расхождениях
проверочного набора. У каждого предложения видны примеры-основания. Его можно
отредактировать, принять или отклонить. Принятие включает правило в следующие
анализы; отключение уточнения возвращает прежнее правило. Исходный файл правил
не переписывается. После изменения правил стоит повторить проверку модели:
старый отчёт помечается как относящийся к другой редакции.

По умолчанию выбран Codex CLI с входом пользователя. Путь можно задать через
`codex_binary`, модель — в интерфейсе. OpenRouter настраивается независимо
для текста и картинок. Ключ: `OPENROUTER_API_KEY` или файл `openrouter_key_file`.
Запросы OpenRouter платные; автоматического повтора ошибок нет.
Ответы и квитанции сохраняются локально.

Для проверки через Codex установите CLI отдельно и выполните `codex login`.
Для OpenRouter задайте свой ключ и выберите провайдера в настройках.
Обычное редактирование доступно без подключения ИИ.

Редактор и парсер Markdown работают локально. При запуске ИИ-проверки
текст, личные правила и выбранные примеры прошлых решений передаются
настроенному исполнителю. Условия обработки зависят от выбранного сервиса.
Отправка на сайт или в Telegram запускается отдельным действием.

ИИМетр показывает отклонение от выбранного авторского корпуса и редакторские
признаки. Это не детектор авторства и не «процент ИИ». Личные тексты не входят
в поставку. В «Разборе» нажмите **Настроить сравнение голоса**, выберите папку
собственных Markdown-текстов и **Подключить и пересчитать**. Подпапка `talks`
используется для докладов. Выбор хранится в личном состоянии отдельно от машинного
конфига; прежний `voice.corpus_dir` остаётся исходной настройкой. Корпус читается
локально и не меняется. Без корпуса итоговая числовая оценка не показывается;
причина отсутствия сравнения видна, а словарь и структура остаются доступны.

В «Разборе» кнопка подсветки показывает число найденных словарных оборотов.
Они подчёркиваются и внутри редакторских пометок; щелчок по пометке по-прежнему
открывает её карточку. Словарные находки и структура доступны без корпуса.
Отсутствие совпадений не означает отсутствия шаблонной подачи: этот локальный
словарь не анализирует смысл и развитие статьи.

**Разобрать статью целиком** во вкладке «Замечания» проверяет композицию,
логику и конкретику, повторы мысли, риторические шаблоны и личные правила.
Модель сначала составляет карту статьи, затем формулирует замечания и отдельным
запросом перепроверяет каждое с возражением в пользу автора. Если кандидатов нет,
третий запрос пропускается. Это до трёх запросов к выбранному исполнителю;
для OpenRouter действуют его тарифы.

Перед смысловыми проходами локально ищутся похожие предложения, повторные
начала абзацев, серии оговорок и коротких блоков. Эти подсказки с точными цитатами
помогают модели искать пропуски. Их можно раскрыть в отчёте и оценить самостоятельно.

Одно замечание может связывать несколько цитат. Нажмите цитату, чтобы перейти
к ней; связанные места выделяются бирюзовым подчёркиванием. В карточке видны
последствия для читателя, предлагаемое действие и контраргумент. **В работу**,
**Не согласен** и **Учтено** сохраняют решение и комментарий без изменения текста.
При следующем разборе этой статьи модель получает последние 20 таких решений.
В блоке «Что проверено» видны все пять направлений, в том числе те, где оснований
для замечания не хватило. Отклонённые при перепроверке претензии тоже доступны.

Разбор привязан к версии. После правки текста он остаётся у прежней версии;
для новой нужен новый запуск. Защищённые места используются только как контекст.
Подробности и границы проверки: [docs/DEEP-REVIEW.md](docs/DEEP-REVIEW.md).

Голос требует `faster-whisper` в интерпретаторе `speech.python` и моделей
в `speech.model_dir`. Язык, модели и режим без сети настраиваются.
Обычное редактирование работает без этой дополнительной зависимости.

## Публикации

**Анонс** открывает два формата Telegram: короткий анонс с вложениями и статью
с картинками и видео между абзацами. Можно добавить PNG, JPEG, WebP и MP4,
выбрать файл из материалов статьи, изменить порядок альбома или убрать вложение.
Видео ограничено50МБ, картинка10МБ, общий размер файлов одной отправки50МБ.
В альбоме до10файлов, включая обложку; подпись со ссылкой — до1024символов.
Обычный текст без медиа — до4096символов. Оба черновика сохраняются отдельно.

В формате статьи кнопка **Взять текст текущей статьи** копирует Markdown без
служебных полей. Вставляйте медиа отдельным абзацем: `![Подпись](статья.assets/видео.mp4)`.
Кнопка добавления делает это за вас. Используется Telegram Rich Messages;
отображение зависит от версии клиента. Локальный редактор ограничивает такую
статью60000символов и30локальными медиа. Ссылочные Markdown-вставки вида
`![подпись][ref]` для этого формата пока не поддерживаются.

Анонс также предлагает варианты текста, сохраняет черновик и копирует его.
Во вкладке **Бот и канал** поле **Публикация** выбирает **От имени канала — через бота**
или **Вручную в Telegram**. При отправке ботом предпросмотр показывает канал.
Ручной режим оставляет сохранение и копирование текста, но запрещает отправку
из Гранки, в том числе из другой вкладки со старым предпросмотром. Фото и видео
в этом режиме добавляются в Telegram вручную; там же выбирается аватар отправителя.
Гранка не входит в личный аккаунт и не переключает его профиль. Подписи авторов
настраиваются в самом Telegram. Прежние настройки продолжают использовать канал.
После выбора нажмите **Сохранить настройки Telegram**.

Здесь же настраиваются свои бот и канал. Токен хранится
в личном каталоге данных, читается из файла или `GRANKA_TELEGRAM_BOT_TOKEN`.
Перед отправкой показываются точный пост, файлы и канал. Подготовка копирует
вложения в отдельный снимок, поэтому замена исходного файла его не меняет.
Неизвестный результат
требует проверки канала, повторная отправка блокируется.

**На сайт** готовит локальный снимок и отправляет его на подключённый WordPress
после предпросмотра и отдельного подтверждения. Можно использовать один сайт,
либо упорядоченный маршрут с промежуточными площадками. Git необязателен.
Каждый переход требует подтверждения. Интеграция выключена до настройки
в **Настройки → Публикация на сайт**; используются ваши SSH-доступы,
а репозиторий нужен только при включённом Git.
По умолчанию на конечном сайте создаётся черновик. Ошибка включённого Git или сторонние правки
останавливают перенос; чужие подготовленные файлы не включаются в коммит.

После публикации над текстом видны ссылка и опубликованная версия.
Редактируйте статью обычным образом, сохраните её и нажмите **Обновить на сайте**.
Новый снимок проходит выбранный маршрут. Адрес и дата сохраняются;
перед записью Гранка проверяет, не изменили ли страницу отдельно в WordPress.
Материал, опубликованный ранее вне Гранки, откройте из настроенной папки
исходников сайта: перед первым обновлением будет показана существующая страница.

**Календарь** в верхней панели открывает план статей и Telegram из любого
режима редактора. Его можно открыть сразу по адресу `/#calendar`.
Markdown-черновики из рабочих папок появляются в очереди автоматически,
даже если их ещё не открывали в редакторе. Папки можно ограничить через
`planning.source_dirs`. Служебные файлы, каталоги картинок и исходники
со статусом `publish` не включаются в очередь.

Добавляйте идеи, связывайте их с текущей статьёй, меняйте состояние и дату
в карточке. Материал можно перетащить на день, на другую дату или обратно
в очередь. **Вернуть без даты** оставляет его в планировании;
**Исключить** убирает из распределения. Список исключённых позволяет вернуть
материал. Эти действия не удаляют статью. Закреплённая дата защищена
от перетаскивания; опубликованная дата из квитанции доступна только для чтения.

Готовность считается по четырём этапам: есть текст, заполнены редакторские
вставки, текущая версия проверена и замечания разобраны, автор подтвердил
готовность. В карточке видно, что осталось. Можно задать свою оценку в процентах;
метка «Готово» означает 100% по решению автора. Процент отражает ход подготовки,
а качество текста остаётся предметом редакторской проверки.

**Распределить даты** назначает дни материалам без даты, сначала готовым,
затем черновикам с более высокой готовностью. Идеи включаются отдельно. Выберите дни недели и число
материалов в день, посмотрите предложение и примените его.
Запланированная дата не запускает автоматическую отправку. Успешные публикации
сайта появляются в календаре по квитанциям.

## Данные и конфигурация

### Доска проектов Blatero

Локальный `tools/blatero_export.py` предоставляет календарь, названия, даты,
готовность и ссылки на статьи для режима «Проекты» Blatero. Мост работает и при
закрытом редакторе, используя те же настройки и расчет календаря. Он не меняет
тексты и даты, не применяет редакторские решения и не запускает публикацию.
Blatero хранит собственные карточки и показывает изменения исходного материала.
Снимок содержит личные названия и пути; его не включают в репозиторий.

| Данные | Расположение |
|---|---|
| Конфигурация | `granka-config.json` или файл из `GRANKA_CONFIG` |
| Выбранные файлы и папки | `library-locations.json` в личном каталоге данных |
| Личное состояние | `GRANKA_STATE_DIR` или системный каталог приложения |
| Статьи и разметка | Папки из `roots` |
| Картинки статьи | `<имя>.assets/` рядом с Markdown |
| Корпус и профили | Пути из `voice` |
| Задания и журналы публикаций | Личный каталог данных |

На Windows состояние по умолчанию — `%LOCALAPPDATA%/Granka`,
на Linux — `$XDG_DATA_HOME/granka` или `~/.local/share/granka`,
на macOS — `~/Library/Application Support/Granka`.
Конфигурацию, токены, статьи и корпус нельзя включать в публичный репозиторий.

## Разработка

```sh
python -m pip install -r requirements-dev.txt
python -m playwright install chromium
python -B -m unittest discover -s tests -q
python tools/release.py --check
```

На Windows проверки используют Edge; браузер можно выбрать через
`GRANKA_BROWSER_CHANNEL`. Парсер Markdown собирается в `tools/markdown-build`:
`npm ci --ignore-scripts`, затем `npm run build`.
