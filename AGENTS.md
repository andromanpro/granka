# Работа с Гранкой

Начинай с README и ARCHITECTURE. Тесты используют временные каталоги;
не применяй решения и не публикуй пользовательские статьи при разработке.

## Конфигурация

Машинные пути, адреса и доступы находятся в локальном конфиге.
В примерах используй домены `.example.invalid`. Личные материалы, корпус,
журналы, токены и результаты заданий не должны попадать в Git.
Сохраняй совместимость версий статей и защиту от конфликтов.

## Проверка и выпуск

- `python -B -m unittest discover -s tests -q`
- `python tools/release.py --check`
- `python tools/public_audit.py`
- `git diff --check`

`VERSION` содержит MAJOR.MINOR.PATCH. CHANGELOG и DEVLOG имеют раздел
с тем же номером и датой. Коммить только явные пути и сохраняй чужой индекс.
Не добавляй инструментам Co-Authored-By.

После коммита `tools/release.py --tag` создаёт аннотированный тег.
Не перемещай опубликованные теги. Перед отправкой проверь remote
и существующую авторизацию. Выпуски в закрытом Gitea продолжаются в обычном порядке.
Пауза публичного выпуска относится к GitHub: публикация туда требует отдельного запроса.
Старую закрытую историю нельзя включать в чистый публичный экспорт.

Автоматические PR обновления зависимостей через Dependabot отключены по решению
автора 29.10.2026. Не включать их повторно без запроса автора. Зависимости
обновлять при подготовке версии с проверкой совместимости; уведомления GitHub
об уязвимостях остаются включёнными.

Публичная main GitHub очищена от авторства Dependabot 29.10.2026. Перед следующей
публикацией брать актуальную публичную main; не возвращать старую историю
слиянием или отправкой прежнего зеркала. Теги выпущенных версий сохранены.
