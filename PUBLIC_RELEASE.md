# Подготовка публичной версии

## Текущие файлы и история — разные проверки

```sh
python tools/public_audit.py
python tools/public_audit.py --history --report /path/outside/repo/history-audit.json
```

Сканер ищет секреты, личные пути и адреса, пользовательские данные и журналы.
В отчёте указываются файл, строка и тип находки; значения секретов не печатаются.
Дополнительные частные строки можно передать через `--policy` с JSON-массивом,
хранящимся вне публичного репозитория.

Это проверка типовых признаков, а не доказательство отсутствия любых секретов.
Перед первым публичным выпуском просмотрите состав файлов вручную.
Лицензия проекта — MIT, полный текст находится в `LICENSE`.
Лицензии включённых сторонних компонентов лежат в `static/vendor`.

## Чистый экспорт

```sh
python tools/public_export.py --output /path/outside/repo/granka-public.zip
```

Экспорт требует чистого рабочего дерева и проверенного текущего коммита.
Он содержит только отслеживаемые файлы текущей версии, без `.git`, старых
коммитов, локального конфига, корпуса и рабочих данных. Перед упаковкой
содержимое проверяется ещё раз.

Для будущего GitHub распакуйте архив и создайте **новый** репозиторий.
Не добавляйте публичный remote к закрытой рабочей истории и не отправляйте
её через `--mirror`, `--all` или вместе со старыми тегами. Удаление личного
файла новым коммитом не удаляет его из прежних коммитов.

Экспорт сам ничего не публикует и не меняет историю исходного репозитория.
