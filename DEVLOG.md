# Дневник разработки

## [1.4.0] - 2026-10-28

Linux CI уточнил синхронизацию теста приправ: старт фонового worker ещё не
означает получение POST-ответа браузером. Тест держит worker до появления
подсветки абзаца, проверяет неизменность текста и освобождает его даже при ошибке.

Два Windows CI-прогона выявили ERR_NO_BUFFER_SPACE на разных статических и API-
запросах. Локальный HTTP/1.0 создавал новое соединение для каждого ответа. Сервер
переведён на HTTP/1.1 с явной длиной всех ответов, включая 416; ошибки с непрочитанным
телом закрывают соединение. При остановке атомарный барьер запрещает новые запросы
и проверяет активные обработчики и задания. Idle keep-alive потоки не задерживают
выход, но выполняющаяся запись блокирует остановку. Отдельные проверки покрывают
повторное использование сокета, framing диапазонов, отказ POST и обе ветви остановки.

Windows CI выявил гонку Telegram → Back: страница уже показывалась, а запись
history откладывалась до ответа настроек. Детерминированный тест с удержанным
HTTP-запросом воспроизвёл ошибку локально. History теперь фиксирует видимую страницу
сразу; Back/Forward во время запроса ставится в очередь и отменяет устаревшее
завершение перехода. Новая проверка удерживает запрос при движении в обе стороны.

Фиксированный маршрут NAS/стейдж/прод заменён на site.pipeline и произвольные
идентификаторы подключений. Последняя включённая площадка получает выбранный
статус статьи; первая не требует фиктивного подтверждения предыдущей. Git
необязателен. Старые конфигурации выводят порядок из прежних имён и сохраняют
сценарий автора; квитанции без pipeline читаются как прежняя тройка.
Подготовка хранит подпись целевых подключений и порядок; смена адреса/SSH/WP/Git
требует новый снимок. Название и маршрут прокси можно менять без пересборки статьи.
Операция удерживает свою конфигурацию до завершения; следующая читает свежую.

Публичный выпуск 1.3.0 остаётся прежним; установщик 1.3.1 готовится отдельно.
Личная конфигурация автора переносится только в его профиль, не в дистрибутив.

## Telegram и маршруты сайта — 2026-10-28, не выпущено

Добавлены create/update с цепочкой квитанций, сохранёнными message_id и проверкой
истории перед отправкой. OS-блокировка охватывает prepare/publish и восстановление
прерванной отправки. Проверены настоящие два процесса и аварийное завершение
владельца: активное sending не превращается в unknown от простого чтения истории,
после аварии повтор блокируется. Текст, Rich Messages, фото/видео и альбомы
обновляются edit-методами без запасной отправки; размер альбома сохраняется.
В интерфейсе добавлен выбор действия и видимый возврат к статье с сохранением ввода.

«Подготовить переход» падал на прямом SSH-соединении к внешнему серверу.
Проверка через системный HTTP CONNECT подтвердила рабочий маршрут. Для каждого
контура добавлен выбор в Настройках, без изменения глобального SSH/proxy.
Настройки ИИ и подключений сохраняются одним атомарным заменением с ревизией
и OS-блокировкой. Начатая операция держит собственную конфигурацию.
В настоящей локальной EXE 1.3.1 параметры сохранены через UI, стейдж проверен
кнопкой «Подготовить переход». Реальный Telegram и deploy не запускались;
статья v28 сохранила исходный SHA256. Полный прогон: 279 тестов, включая
изолированные браузерные проверки; макеты формы просмотрены на 1440 и 390 px.

## Сохранение в Windows — 2026-10-28, не выпущено

После восстановления Medium-меток настоящий EXE импортировал изображение и MP4,
сохранил v28, но следующая атомарная замена JSON получила WinError5. Отдельный
тест с настоящим Windows-дескриптором без FILE_SHARE_DELETE воспроизвёл такой
отказ. Это подтверждает уязвимость механизма сохранения к занятым файлам;
владельца блокировки исходной статьи пока не установили. Добавлены максимум
восемь попыток замены с ожиданием суммарно около секунды. Сама операция над
документом выполняется один раз. После ожидания заново сверяется ревизия,
поэтому чужую правку повтор не перезаписывает. Проверены временный и постоянный
отказы, конфликт, посторонняя ошибка и настоящий Windows-дескриптор.

## Не выпущено — 2026-10-27

У проверки Telegram не было индикации ожидания, а ошибка общего обработчика
попадала в статус другой, скрытой вкладки. Добавлен постоянный результат рядом
с кнопкой: ожидание, бот/канал/ID или ошибка; при незаписанных настройках проверка
не обращается к старому подключению. Браузерная регрессия проверяет задержку,
успешный ответ и отказ в правах без реальной отправки. Защита постоянного
хранения токена Windows DPAPI/диспетчером учётных данных внесена в план;
сейчас файл токена остаётся открытым текстом.

На NAS обнаружено переполнение MP4: тема ограничивала ширину img, но не video,
поэтому браузер показывал исходные 1920 пикселей внутри более узкой колонки.
Ограничение ширины и автоматическая высота добавлены в HTML экспортёра, чтобы
снимок работал и на темах без собственного оформления видео. Теги и файлы
выпущенной 1.3.0 не меняются. NAS обновляется новым неизменяемым снимком.

## [1.3.0] - 2026-10-27

Верхняя строка прежде показывала редакторское поле `draft` даже у выпущенной
статьи, которую библиотека уже считала опубликованной. Добавлена проекция
подтверждённых каналов из существующих API каталога, квитанций сайта и Telegram.
Исходники и редакторские состояния ради этой метки не меняются. Защита от
запоздалого ответа при смене статьи и обновление после отправки сохраняют
контекст; черновики, предпросмотр и неизвестный исход отправки исключены.

Справка открывается отдельным разделом без потери незавершённого ввода.
`docs/USER-GUIDE.md` служит источником встроенного текста; восемь снимков
сделаны на учебном документе с отдельным состоянием, без вызовов модели и отправок.
Проверки добавлены для подтверждений, частичного выпуска, связанных копий
и возврата из справки с незавершённым исходником.

Тёмная мастерская перенесена из утверждённого макета в рабочую Гранку.
Сохранены настоящий DOM редактора, обращения к API, ревизионные проверки
и защита незавершённого ввода. Библиотека, календарь, Telegram и настройки
работают как немодальные разделы рядом с постоянным меню. Галерея картинок,
подтверждения и предупреждение о несохранённой правке остаются модальными.
Настройки генерации поверх галереи сохраняют её текст и место вставки.

При полном прогоне обнаружилось скрытие списка версий после сравнения из
истории. Для этого маршрута список оставлен слева, чтобы можно было вернуть
снимок в работу. Новые браузерные проверки дополнительно контролируют
навигацию назад, живой черновик Telegram без отправки и локальные параметры
чтения. Новое оформление включено в состав Windows-поставки 1.3.0.

При серийном браузерном прогоне прямых ссылок обнаружены отказы соединений
на загрузке отдельных JS-модулей; граф импортов обрывался до создания granka.
У ThreadingHTTPServer стандартная очередь ожидания равна пяти. Введён локальный
подкласс с очередью 128; сетевой тест удерживает accept и проверяет очередь
из 20 одновременных соединений с последующей успешной отдачей всех ответов.

Автор выбрал «Скобочки»: две светлые дуги и коралловая третья. Основной логотип использует Georgia в кривых. Обновлены ресурсы интерфейса и сборка иконок; светлая, одноцветная и малые версии хранятся отдельно. Windows-поставка получила тот же комплект.

Проверены обновления Actions, Markdown и Python. Для JS-пакетов пересобраны
поставляемый парсер и лицензии. У парсера теперь формат ES module; редактор и
Telegram импортируют функцию отрисовки напрямую. Совместимый window.GrankaMarkdown
оставлен для диагностики. После перезагрузки браузерные тесты ждут готовность
редактора, а не обращаются к ещё не созданному глобальному объекту. Ресурсы
фикстуры освобождаются и при неудачном setUp; в диагностике видны ошибки загрузки.

Отдельно воспроизведён пропуск результата анализа при опережающих часах клиента:
прежний фильтр сравнивал только finished и loadedAt. Текущие задания теперь также
учитываются по ID. Регрессия падает с прежним фильтром и проходит с новым.

Список Windows wheel-файлов синхронизирован с runtime requirements. До распаковки
проверяются имя и версия из METADATA, помимо уже существующей SHA256-проверки.
Выпущенные теги и бинарные файлы 1.2.3 не заменялись.

В 1.3.0 установщик и переносимый архив собираются с новой мастерской,
встроенной справкой и полным комплектом руководств с изображениями.
Настройки и статьи по-прежнему хранятся отдельно от файлов программы;
проверка поставки использует отдельное временное состояние.

## [1.2.2] - 2026-10-25

Telegram разделяет короткий анонс с вложениями и rich-статью. Файлы загружаются
в assets конкретной статьи с проверкой ревизии и содержимого. Подготовка
сохраняет отдельные копии и SHA256; перед отправкой снимок перепроверяется.
Один файл отправляется через sendVideo/sendPhoto, альбом — одним sendMediaGroup.
Неоднозначный ответ всего альбома блокирует повтор. Старые идентификаторы
обычных текстовых постов и обложек сохранены для совместимости журнала.

В rich-статье самостоятельные Markdown-вставки преобразуются в tg-медиа
и multipart-вложения sendRichMessage. Предпросмотр использует тот же порядок,
после подготовки читает снимки. Ссылки на локальные файлы вне assets и
неподдерживаемая запись медиа отвергаются. Режим не создаёт страницу Telegraph.
Реальная отправка в канал требует отдельного действия пользователя; тесты
проверяют контракт с подменённым транспортом и не подтверждают приём сервером Telegram.

## [1.2.1] - 2026-10-24

История теперь разделяет версии и события. Открытие снимка сохраняет режим
чтения, а возврат добавляет новую вершину с `restored_from`, сохраняя прежнюю
цепочку. Пометки выбранного снимка копируются с новыми ID и ссылками на
исходные; текст и обложка возвращаются вместе. Даже одинаковый текст может
получить новую версию для восстановления прежних пометок.

Сравнение хранит независимую пару версий в состоянии интерфейса. Выбор пары
не меняет документ; смена открытой версии возвращает обычную исходную пару.
Переходы и сравнение используют общую защиту незавершённого ввода. Возврат
проверяет ревизию и повтор операции; запись Markdown допускается, только
если он соответствует одному из сохранённых снимков и не изменился за
время операции. Неизвестная внешняя редакция остаётся на диске с предупреждением.

## [1.2.0] - 2026-10-24

Приправы используют общий механизм рецептов вместо отдельного режима для
каждого приёма. Флаконы и текстовые строки — два представления одной правой
панели. Нативное перетаскивание выбирает конкретный абзац через адресацию
Markdown в символах Unicode; для клавиатуры и сенсорного ввода есть явный выбор.
Разные сосуды нарисованы в CSS: солонка, мельница, банка с травами и капельница.

Задание spice сохраняет снимок, запрос, ответ и проверенные предложения,
не меняя статью. Границы, повторные цитаты, пересечения, защищённый текст,
код, ссылки и цитируемые блоки проверяются на сервере. Выбранные замены
применяются только к исходной ревизии через обычные неизменяемые версии.
Внешне изменённый Markdown не перезаписывается; интерфейс показывает причину.
Рецепты находятся в личном каталоге состояния и проверяют свою ревизию.
Разовое использование не меняет авторские правила.

## [1.1.0] - 2026-10-17

Переход из Blatero к Markdown использует root и source_file. Выбор проверяется
по каталогу и его раскрываемым копиям; отсутствие файла не подменяется первым
документом или поиском по заголовку. Создание разметки остаётся в общем маршруте
открытия редактора и не меняет Markdown.

Библиотека и календарь читают подтверждённые публикации наравне с черновиками.
Явные связи исходника с URL и датой хранятся в локальной конфигурации;
объединение копий опирается на этот адрес. Текст статьи и история не меняются.
Сохранённый статус черновика больше не перекрывает подтверждённый выход;
календарный ID и личные заметки сохраняются. Для публикаций без Markdown
календарь даёт внешнюю карточку библиотеки. Проверки покрывают ссылки, даты,
переход без создания документа и исключение выпущенного из распределения.
Адресные исключения файлов и подпапок не заменяют чтение всей рабочей папки:
новые Markdown-материалы продолжают появляться автоматически.

Глубокий разбор выделен в отдельное задание. Контракт локальной замены не мог
представить повтор одной мысли в нескольких разделах, перестановку блоков
или отсутствие примера. Новый режим строит карту статьи, формулирует до 12
существенных претензий, затем проверяет каждую в отдельном запросе той же
модели. Контраргумент обязателен; перепроверка может отклонить все замечания.
Эта схема не измеряет машинное авторство и не делает ответы независимыми.

Реальный пилот показал ограничение перепроверки: она способна оправдать
каталог возможностей жанром обзора и не предъявить претензий к риторике.
Поэтому диагноз и перепроверка получают локальные подсказки лексических
повторов, одинаковых начал абзацев, серий оговорок и коротких блоков. Группы
с точными цитатами доступны автору независимо от вердикта модели; они не
повышают ИИМетр и не становятся ошибками автоматически. Перепроверка явно
может оспорить карту. Нужна авторская разметка полезных и пропущенных замечаний;
один пилот не измеряет чувствительность.

Цитаты сверяются с исходным Markdown до и после перепроверки; защищённые места
не становятся целями правки. Отчёт и авторские решения хранятся отдельно от
аннотаций-замен, не меняют статью и не переносятся на новую версию автоматически.
До трёх запросов запускаются только отдельной кнопкой с пояснением расходов;
каждый этап сохраняет ответ и квитанцию. Частичный сбой и ревизионный конфликт
оставляют результат в журнале, без автоматического повтора.

Windows-поставка содержит официальный переносимый Python 3.14.8, зависимости
и официальный Codex CLI. Они не регистрируются в системе и не меняют PATH.
Сборка проверяет закреплённые SHA256 загрузок и отдельный список файлов
приложения. Личная конфигурация и данные из рабочего дерева не копируются.
Inno Setup устанавливает программу для текущего пользователя без повышения
прав; состояние находится отдельно в LocalAppData/Granka. Удаление программы
не удаляет статьи. Демо появляется только в пустом первом запуске.

Нативный launcher открывает браузер через встроенный Python без консоли.
Для подключения Codex предусмотрен отдельный запуск браузерного входа;
он не передаёт статьи и не запускает запросы к модели. Остановка сверяет
идентичность своей копии и блокируется незавершённым заданием. Установщик
проверяет mutex работающей поставки и не завершает её принудительно.

Кандидат создаётся из текущих файлов явным --allow-dirty и помечается в имени
и манифесте. Штатная сборка требует чистое дерево. Подписи сертификатом нет;
обход защит Windows не применяется. Публичный тег и выпуск создаются отдельно.

ИИМетр находил обороты, но редактор удалял все пересечения с существующими
пометками. Рендер теперь делит текст на интервалы с одинаковым набором пометок:
основная карточка сохраняет цвет и щелчок, словарное совпадение добавляет
пунктирное подчёркивание и пояснение. Обёртки остаются служебными и не меняют
Markdown. Состояние кнопки, счётчик и aria-pressed обновляются вместе.

Отсутствие корпуса блокирует только сравнение голоса и итоговую оценку.
Словарные и структурные показатели видны самостоятельно; ноль совпадений
сопровождается объяснением границ словаря. Выделение внутри фразы больше
не разрывает словарное совпадение; код и адреса по-прежнему маскируются.
Версия локального движка — 0.3 для обновления отпечатков профиля.

До исправления браузерные пробы воспроизвели потерю подсветки, неверную кнопку
после смены версии и скрытые показатели без корпуса; модульная проба — пропуск
Markdown-выделения. Эти сценарии добавлены к регрессии. Чувствительность к
смысловым и композиционным шаблонам этим исправлением не заявляется.

## [1.0.0] - 2026-10-16

Номера 4.x ниже — внутренние редакции закрытой разработки. Функциональная база
1.0.0 соответствует проверенному кандидату 4.8.0; номер не относится к версии
статьи и не меняет формат её данных. Публичный репозиторий начинается новым
снимком текущих файлов, прежняя закрытая Git-история остаётся отдельно.

Проверены 136 модульных и браузерных сценариев, запуск отдельной поставки,
выбор источников и защита несохранённого текста. Системный диалог в тестах
подменяется; отсутствие Tk обрабатывает ручной путь.

## Архив внутренних версий

## [4.8.0] - 2026-10-16

Картинки вставлялись, но убрать их можно было только в исходнике: щелчок по
иллюстрации ничего не выделял, а Delete в этот момент относился к соседнему
тексту. Теперь щелчок выделяет иллюстрацию целиком и подсвечивает её рамкой,
Delete и Backspace убирают выделенное. То же действие есть в меню выделения и
в контекстном меню на самой картинке.

Выделение мышью через несколько иллюстраций убирает их одной командой.
Если абзац держал только картинку, он исчезает вместе с ней.

Удаление блока теперь забирает и разделитель после него. Раньше на месте
удалённого абзаца оставались лишние пустые строки, и Markdown постепенно
разъезжался. Служебный признак выделения не попадает в сравнение блоков,
поэтому подсветка не превращается в правку текста.

У нативных списков Windows светлый фон мог сочетаться со светлым текстом
страницы. Для option и optgroup явно заданы цвета темы. Проверка в браузере
измеряет контраст в светлой, тёмной и высококонтрастной системных темах,
а также проверяет переключение версии клавиатурой без изменения документа.

Мост Blatero читает календарь из штатных источников и не меняет статьи.
Ссылки с root/f открывают выбранный документ; source открывает поиск.

Для первого публичного выпуска выбрана MIT. Подготовка использует отдельный
снимок текущих файлов: прежняя закрытая история, личная конфигурация, корпус
и журналы не переносятся. Добавлены проверки GitHub Actions для Windows и
Linux; результаты их удалённого запуска будут доступны после публикации.

В библиотеке добавлены выбор файла и папки. Системное окно работает в отдельном
процессе Python с Tk, чтобы не запускать графический цикл внутри HTTP-потока.
Без Tk доступен ручной путь. Реестр источников живёт в личном состоянии,
использует ревизию и атомарную запись и не меняет конфиг. Отдельный файл
сканируется без соседей; подключённая папка доступна библиотеке, календарю
и мосту Blatero. Отмена выбора ничего не создаёт. Copyright приведён
к авторской подписи androman (androman.pro).

Смена документа и версии больше не требует сначала разбираться с заблокированным
списком. При несохранённых изменениях открывается диалог с тремя действиями:
сохранить и перейти, перейти без сохранения, остаться. Библиотека и календарь
используют ту же проверку. Отказ от перехода не создаёт разметку нового файла;
конфликт сохранения оставляет текущий текст в редакторе. Предупреждение браузера
при закрытии вкладки и локальное восстановление черновика сохранены.

## [4.7.0] - 2026-09-17

Календарь считал только вручную заведённые карточки и квитанции публикаций.
Markdown-файлы, которые ещё не открывали в редакторе, в очередь не попадали:
распределять было нечего. Новый модуль читает черновики из настроенных папок.
Чтение и планирование не создают разметку и не меняют исходный текст.
Редактор открывает выбранный Markdown отдельным действием пользователя.

Библиотека читает тот же каталог, показывает заголовки и разделяет черновики
и опубликованные материалы. Служебные файлы исключены из выдачи. Копии,
связанные квитанцией экспорта, одинаковым slug или точным текстом в одном корне,
сгруппированы с доступом к каждому исходнику. Физические файлы сохраняются.

Идентификатор материала сохраняется при появлении разметки. Даты, личная
оценка и исключения хранятся отдельно от статьи. Исключённый файл не возникает
снова при следующем сканировании; его можно вернуть в план. Изменение исходника
делает старый предпросмотр распределения недействительным.

Готовность показывает четыре этапа: наличие текста, заполнение вставок,
проверку текущей версии с разобранными замечаниями и подтверждение автора.
Это индикатор процесса подготовки. Автор может указать свою оценку или
отметить материал готовым. Выполнение отдельного поручения ИИ не считается
проверкой всей статьи.

Проверены импорт обычных черновиков, предпросмотр и сохранение распределения,
исключение и возврат, перетаскивание между датами, открытие исходника из карточки
и неизменность Markdown при работе с планом.

Пройдено 127 модульных и браузерных тестов. На рабочей библиотеке проверено
совпадение набора черновиков с календарём, группировка экспортной копии,
распределение найденных материалов без изменения файлов и сохранённых дат.

## [4.6.1] - 2026-09-17

Вход в календарь находился в панели форматирования статьи. При переходе
к исходнику или сравнению эта панель скрывалась вместе с кнопкой плана.
Теперь отдельная кнопка «Календарь» находится в верхней панели приложения.
Прямая ссылка `/#calendar` открывает его при загрузке, закрытие убирает
этот адресный фрагмент. Календарь остаётся доступен без выбранной статьи.

Браузерная проверка календаря дополнена доступностью из трёх режимов,
открытием по ссылке и закрытием по Escape. Даты и правила распределения
используют существующее личное хранилище.

Пройдено 117 тестов. В работающем приложении отдельно проверены прямая ссылка,
пустая библиотека и отсутствие переполнения панели на ширинах 320–1440 пикселей.

## [4.6.0] - 2026-09-16

После публикации редактор показывает ссылку, опубликованную версию и наличие
локальных изменений. Обновление проходит ту же цепочку предпросмотра,
стейджа и прода. Адрес, исходная дата и файл сохраняются; существующий пост
обновляется по его идентификатору. Снятие с публикации названо явно.

План публикаций отделён от заданий отправки. Даты можно назначить вручную
или распределить по дням недели с ограничением числа материалов в день.
Перед применением виден результат. Распределение учитывает занятые даты,
сохраняет уже назначенные и не запускает публикацию. Изменение плана в другой
вкладке отменяет устаревшую операцию. Квитанции успешных публикаций сайта
появляются в календаре автоматически.

Реальная обкатка выявила отказ SSH до соединения и повторную загрузку уже
доставленной обложки. Повтор допускается только при доказанном отказе
до запуска команды. Оборванная команда не переигрывается. Файл картинки
сохраняет имя по хешу, ранее загруженные картинки распознаются отдельно.

Пройдено 117 модульных и браузерных тестов. Проверены предпросмотр и применение
распределения, неизменность статьи при работе с планом, обновление по прежнему
идентификатору и отображение опубликованной версии. Реальная статья прошла
все три контура, затем получила иллюстрации через обновление того же поста.
Аудит текущих файлов не нашёл личных настроек или секретов.

## [4.5.0] - 2026-09-16

Подстройка оформлена как предложения, которые включаются после решения автора.
Модель видит историю решений, действующие правила и расхождения последней
проверки; она должна указать подтверждающие примеры. Выдуманные ссылки
отклоняются до сохранения. Одно решение не трактуется как универсальный запрет.

Принятые формулировки хранятся отдельно от исходного файла предпочтений.
Уточнение заменяет конкретное правило; его отключение восстанавливает прежнее.
Изменения исходных решений и ревизии правил проверяются при принятии.
Отвергнутые и отключённые формулировки учитываются при следующих предложениях.

Проверка модели сохраняет редакцию правил, с которой выполнялась. После правок
старый результат не выдаётся за оценку текущей настройки. Регрессионный набор
проверяет знакомые авторские решения и не является оценкой на новых текстах.

Пройдено 105 модульных и браузерных тестов. Реальный запрос подготовил два
предложения с проверенными ссылками на решения. Действующие правила и версия
статьи при этом остались прежними; включение предложений ожидает выбора автора.

## [4.4.0] - 2026-09-16

Личные правила раньше сохранялись отдельно, но не попадали в новый анализ.
Теперь анализ получает их и подходящие примеры прошлых решений. История
связывается по происхождению пометок: перенос между версиями не считается
новым голосованием. Отказ «варианты хуже» отличается от решения сохранить исходник.

Пакет объединяет только нерешённые карточки с одним явным правилом; широкого
класса вроде «неясность» недостаточно. Автор видит каждую замену и выбирает
варианты. Валидация проверяет весь пакет до изменения решений. Отмена не затирает
последующие индивидуальные правки.

Проверочный набор сохраняется локально отдельным снимком. Модель получает
исходные фрагменты и правила, без авторских ответов. Автоматическая метрика
проверяет направление решения, а не смысл произвольной новой формулировки.
При отсутствии отрицательных примеров это ограничение показано в отчёте.

Пройдено 98 модульных и браузерных тестов. Пакеты проверены на полном сохранении,
отмене и отказе всей операции при конфликте. Пилотный локальный предпросмотр
прошёл реальную цепочку Git → WordPress; текст, обложка и страница проверены.
Перенос статьи на стейдж и прод не выполнялся. Выпуск приложения оформлен
в закрытом Gitea; публикация на GitHub остаётся отложенной.

Настройки путей, корпуса, голосовых моделей и WordPress отделены от приложения.

показывает необходимость калибровки; публикация на сайт включается после настройки.

Движок экспорта входит в поставку. OpenRouter обращается к API напрямую

нужен только при пересборке словесного знака.

Личные материалы и отчёты исключены из поставки. Проверка текущих файлов
отделена от истории: очистка HEAD не очищает старые коммиты. Публичный
